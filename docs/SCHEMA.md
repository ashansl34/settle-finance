# Firestore schema and invariants

All collections use string document IDs; timestamps are UTC epoch milliseconds, dates are ISO strings and currency amounts are integer LKR minor units. Every document also contains its own `id`. Firestore client writes are denied. Admin SDK mutations are permitted only through the callable's domain commands. The only data returned to a client is the `project()` view for that authenticated UID.

## Concurrency and repository

### Added personal settings and group invitation records

- `preferences/{uid}` contains `userId` and `dailyLimit` (positive integer minor units). It is owner-readable only and updated through `budget.set`; it is never placed in the public user directory.
- Personal `entries` may include `recipientId` and `paymentKind` (`expense` or `cash_movement`). Friend records are private to their author. A cash movement has `expenseShare: 0`, reducing account cash without counting as spending. Legacy `Cash` account names are treated as `Wallet` for display and aggregation.
- `groupInvites/{uuid}` contains `groupId`, `groupName`, `from`, `to`, `status`, `createdAt`. Only the recipient may accept/decline a pending invitation. Acceptance checks the inviter's current active membership and role; only an admin invitation grants active membership immediately. Ordinary member invitations create pending requests. No acceptance grants an admin role.
- `groupLinks/{randomUUID}` contains `groupId`, `createdBy`, `expiresAt`, `revoked`. Tokens are excluded from every general snapshot and direct Firestore reads/writes are denied. The creating member receives the token once from the callable. Preview returns only group name/ID; joining creates a pending membership. Links expire after seven days, require the creator to remain an active member, and can be revoked together by an admin. Invitation links use a URL fragment to avoid including the token in page HTTP requests.
- The demo adapter adds missing collections when reading older saved datasets, preserving existing balances, loans and accounts.

`finance()` authenticates the ID token, requires a verified phone claim, loads a bounded dataset inside a Firestore transaction, accrues trust, applies a validated command, computes changed documents and writes the result. Firestore retries read conflicts. All reads precede all writes. A wrong-code attempt returns an error field after committing its count and audit record; the client displays the error only after receiving the committed snapshot. A code cannot complete two repayments, and concurrent attempts cannot lose increments. Client views are filtered after commit.

The aggregate adapter is intentionally limited to 400 records per collection and 440 changed documents per request; exceeding either throws `resource-exhausted`, without partial writes. The data cap includes audit and trust event collections and is global to this pilot project. An hourly scheduler applies the same accrual logic; live requests also accrue to the server timestamp. The scheduler's cutoff is settlement time for settled loans. Operationally monitor scheduler failures and collection counts. For production scale, implement domain-scoped repository reads, pagination and bounded per-loan trust transactions before reaching the cap.

## Debt and ledger semantics

An expense split means that participant owes the payer its share. The payer's own share cancels. `netDebts()` reduces the graph to each member's net position, then deterministically pairs debtors/creditors; this offsets cycles as well as reciprocal debts. It never rewrites original records. A group loan remains a separate contractual obligation with its own verification and trust history and is not silently offset against expense debt.

The current UI displays expense settlement suggestions without mutating them as “paid.” Real cash receipts for group expense settlements and pooled-fund spending are future separate ledgers; do not enter a loan repayment to clear an expense balance. Contributions track fund receipts independently, and users may see unequal amounts versus the target rather than a false binary claim that a partial amount meets a member quota.

## Time policy

Loan clocks use elapsed UTC milliseconds, not local midnight. `floor(max(0, cutoff - activatedAt - 72h) / 24h)` gives complete overdue days. The first point event occurs at 96 hours. UI personal accounting dates are entered as local calendar dates; they are not used for security or loan time calculations. The demo seeds dates relative to current runtime time.
